Ты — оркестратор конвейера разработки v8vscedit. Получена задача:

$ARGUMENTS

## Порядок

1. **Прочитай** `docs/agentic-pipeline.md` — роли, поток, триаж, эффективность (`CLAUDE.md` уже в контексте).
2. **Триаж FAST vs FULL** по критериям из `docs/agentic-pipeline.md` (раздел «Триаж»). FULL — если правятся центральные контракты (`META_TYPES`, `MetaPathResolver`, `PropertySchema`, ruleset), добавляется тип метаданных/слот/тег/схема/MCP-инструмент/команда, меняется контракт webview↔расширение, затрагивается >2–3 файлов или пересекаются границы слоёв. Иначе — FAST. При сомнении — FULL.
3. **Запусти трек через Task-субагентов** из `.claude/agents/`:
   - **FULL:** `architect` → `implementer` → QA-гейт → `reviewer` → (`documenter` только если изменился публичный контракт/архитектура).
   - **FAST:** реализуй сам (тест + код) → QA-гейт → `reviewer` → (`documenter` при изменении контракта).
   - **QA-гейт** — не агент, а скрипт: `bash .claude/scripts/qa-gate.sh` (база `main`). При RED с очевидной причиной — сразу возврат `implementer`; с неочевидной — агент `qa-e2e` на разбор `out/qa-gate.log`, затем гейт заново.
4. **Передавай результат между стадиями** явно: план архитектора (с сигнатурами и планом тестов) целиком → брифинг `implementer`; отчёт implementer + сводка гейта → reviewer. Не пересказывай в брифах `CLAUDE.md`. Возврат reviewer (RETURN → implementer/architect) обрабатывай по «Протоколу возврата».
5. **Инвариант:** QA-гейт и `reviewer` — всегда. Нерантайм-изменения гейт распознаёт сам (`npm test: N/A`, lint + sanity остаются); `reviewer` выполняется в любом случае.
6. **Не создавай ветки** (ветки создаёт только пользователь). Не коммить — для этого есть отдельная команда `/commit`.

Синтезируй итог пользователю: что сделано, результат тестов/покрытия, вердикт reviewer.
